## 一、系统架构

系统采用经典 MVC 三层架构，在此基础上引入 AI Agent 层和装饰器链：

```
浏览器 (HTML/CSS/JS)
        ↓ HTTP
Spring MVC DispatcherServlet
        ↓
Controller 层（REST API）
        ↓
Service 层（业务逻辑）
        ↓                    ↓
Database 层              AgentFactory
(H2 / MySQL)              ↓
                      AbstractAgent（模板方法）
                          ↓
                      AiClient 接口（策略）
                          ↓
               RateLimiting → Caching → Logging（装饰器链）
                          ↓
               DeepSeekStrategy / QwenStrategy / KimiStrategy / MockAiClient
```

## 二、MVC 分层说明

### Model 层
- `model/UserProfile`：用户体征数据（Record）
- `model/WorkoutLog`、`NutritionLog`、`BodyMeasurement`、`SleepLog`：各业务数据模型
- `model/AgentReply`：AI 回复封装（含 answer、nextActions、usedContext、model）

### View 层
- `public/pages/*.html`：20 个功能页面，均通过 `<body data-page="X">` + `layout.js` 注入统一侧边栏
- `public/assets/styles.css`：深色主题 CSS 变量系统
- `public/assets/layout.js`：IIFE，自动注入侧边栏并高亮当前页

### Controller 层
- `SpringRestController`：主 REST 控制器，处理用户档案、AI 对话、仪表盘、计划等 API
- `WorkoutController`：训练日志 CRUD
- `NutritionController`：饮食日志 CRUD
- `MeasurementController`：身体测量 CRUD
- `SleepController`：睡眠记录 CRUD
- `ChallengeAchievementController`：挑战赛与成就 API

## 三、设计模式

### 1. MVC 模式
前端页面（View）通过 `fetch()` 调用后端 REST API，Controller 处理请求后调用 Service/Agent，返回 JSON 数据由前端渲染。视图与业务逻辑完全解耦。

### 2. 策略模式（Strategy Pattern）
`AiClient` 接口定义 `complete(system, user)` 方法，由四个策略类实现：
- `DeepSeekStrategy`：调用 `https://api.deepseek.com/chat/completions`
- `QwenStrategy`：调用阿里云 DashScope 接口
- `KimiStrategy`：调用月之暗面 Kimi 接口
- `MockAiClient`：本地模拟，无需网络

`AppConfig` 根据 `ai.provider` 配置在启动时选择具体策略，运行期不切换。

### 3. 装饰器模式（Decorator Pattern）
三层装饰器按顺序包装核心 `AiClient`：

```
RateLimitingAiClientDecorator（60次/分钟限速）
    └── CachingAiClientDecorator（LRU缓存，500条，TTL 30min）
            └── LoggingAiClientDecorator（请求/响应日志）
                    └── 真实 AiClient（DeepSeek / Qwen / Mock）
```

新增功能（限速、缓存、日志）无需修改核心类，符合开闭原则。

### 4. 工厂模式（Factory Pattern）
`AgentFactory.create(type)` 根据类型字符串（fitness / planner / nutrition / recovery / health / mindset）返回对应 `Agent` 实例，Controller 无需知道具体 Agent 类。

### 5. 观察者模式（Observer Pattern）
`LearningEventBus` 实现事件发布-订阅：用户保存档案、记录训练、记录饮食时发布事件，各订阅者（成就检查、数据统计）自动响应，无需 Controller 主动调用。

### 6. 模板方法模式（Template Method Pattern）
`AbstractAgent.reply(message, user)` 定义固定流程：
1. 调用 `systemPrompt(user)` 构建系统提示词（子类实现）
2. 调用 `ai.complete(system, message)` 获取 AI 回复
3. 返回 `AgentReply`（含 nextActions、usedContext）

子类（TutorAgent、PlannerAgent、NutritionAgent 等）只需实现 `systemPrompt()`，复用主流程。

## 四、数据库设计

使用 H2 内存数据库（MySQL 兼容模式），`schema.sql` 自动建表，`data.sql` 插入初始数据。

| 表名 | 说明 |
|------|------|
| users | 用户档案（身高、体重、目标、训练模式） |
| workout_logs | 训练日志（动作、组数、次数、重量、时长） |
| nutrition_logs | 饮食日志（餐次、食物、热量、宏营养素） |
| body_measurements | 身体测量（体脂、肌肉量、各部位围度） |
| sleep_logs | 睡眠记录（入睡/起床时间、质量分、影响因素） |
| plans | 训练计划（标题、日期、步骤） |
| challenges | 挑战赛定义（类型、目标值、奖励积分） |
| user_challenges | 用户参与的挑战及进度 |
| achievements | 用户已获得的成就 |
| ai_conversations | AI 对话会话 |
| ai_messages | AI 对话消息明细 |
| courses | 课程定义 |
| questions | 体能测验题库 |
| attempts | 体能测验记录 |

## 五、AI Pipeline 流程

```
用户输入
    ↓
意图识别（IntentDetector）
    ↓
上下文注入（用户体征 + 历史记录）
    ↓
Prompt 构建（PromptBuilder）
    ↓
安全过滤（SafetyFilter）
    ↓
AiClient.complete() → 大模型 API
    ↓
后处理（格式化、提取行动项）
    ↓
返回 AgentReply
```

## 六、前端架构

所有页面共享同一套 CSS 变量体系（深色主题）和 `layout.js` 侧边栏，通过 `<body data-page="X">` 属性驱动，无任何重复 HTML：

```
layout.js（IIFE）
├── 读取 body.dataset.page
├── 注入 <aside class="sidebar"> （含分组导航）
├── 高亮当前激活页
└── 注入 .app-wrapper 布局容器
```

CSS 核心变量：`--bg`, `--surface`, `--card`, `--border`, `--text`, `--muted`, `--accent`（橙色 #f97316）
